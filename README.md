# Showtime (React + Express + MongoDB)

Movie & live-event booking — browse shows, pick a showtime, select seats, and pay with Razorpay. Use Razorpay **test keys** while developing (no real money moves).

```
showtime-react/
├── src/            React frontend (Vite)  — api.js talks to the backend
└── server/         Express + MongoDB API
    └── src/
        ├── models/   Movie, Venue, Booking, SeatLock
        ├── routes/   movies, venues, shows (seat map), bookings
        ├── utils/    seat tiers/pricing, show validation, errors
        └── seed/     movies + venues seed data
```

## Run locally

Needs Node 18+ and a running MongoDB (local `mongod`, Docker `docker run -p 27017:27017 mongo`, or an Atlas URI).

```bash
# 1. backend
cd server
cp .env.example .env        # edit MONGODB_URI if not using local Mongo
npm install
npm run dev                 # API on http://localhost:5000 (auto-seeds movies/venues on first run)

# 2. frontend (new terminal, project root)
npm install
npm run dev                 # http://localhost:3000 — /api is proxied to :5000
```

`npm run seed` (in `server/`) re-upserts movies/venues any time; it never touches bookings.

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/health` | liveness |
| GET | `/api/movies?genre=Drama` | `genre` optional / `all` |
| GET | `/api/movies/:id` | id is the short code, e.g. `m1` |
| GET | `/api/venues` | `{ venues, times }` |
| GET | `/api/shows/seats?movieId&venue&time&date` | seat map with `taken` flags (date = `YYYY-MM-DD`) |
| POST | `/api/payments/order` | body: `movieId, venue, time, date, seats[], name, email, phone` → holds the seats and creates a Razorpay order; 409 if a seat is taken |
| POST | `/api/payments/verify` | body: `razorpay_order_id, razorpay_payment_id, razorpay_signature` → verifies the signature, confirms the booking |
| POST | `/api/payments/cancel` | body: `{ orderId }` → customer closed the popup; releases the held seats |
| POST | `/api/payments/webhook` | Razorpay → server safety net (see below) |
| GET | `/api/bookings` | this browser's paid bookings |
| GET | `/api/bookings/:id` | one paid booking |

Booking/listing requests carry an anonymous `x-client-id` header (generated by the frontend and kept in localStorage), since the UI has no login — that is what scopes "My bookings".

## How it works

- **No double-booking:** every booked seat is a `SeatLock` document with a unique index on (movie, venue, time, date, seat). Two simultaneous bookings for the same seat can't both succeed; the loser gets a 409 and the UI sends them back to the seat map.
- **Server-side pricing:** the client sends only seat keys; subtotal, fee and total are computed on the server.
- **Demo realism:** ~22% of seats per show are "pre-sold" deterministically so the map doesn't look empty; real bookings are layered on top.

## Razorpay setup

1. Create a Razorpay account and copy your **Test** `Key Id` and `Key Secret` (Dashboard → Account & Settings → API Keys).
2. Put them in `server/.env` (`RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`) and restart the server.
3. Pay in the popup with Razorpay's test methods (e.g. UPI id `success@razorpay`, or the test cards listed in their docs).
4. **Webhook (recommended, needed in production):** Dashboard → Webhooks → add `https://<your-api>/api/payments/webhook`, events `payment.captured` and `order.paid`, choose a secret and set it as `RAZORPAY_WEBHOOK_SECRET`. This confirms bookings even if a customer closes the tab right after paying. Locally, expose port 5000 with a tunnel (e.g. ngrok) to test it.
5. Going live = swap in your **Live** keys (requires Razorpay KYC activation).

**Payment flow**

1. Customer clicks *Pay* → server validates, **holds the seats for `HOLD_MINUTES` (default 15)** and creates a Razorpay order. The amount comes from the server, never the browser.
2. Razorpay Checkout opens in a popup (UPI / cards / netbanking / wallets); card details never touch your server.
3. On success the browser sends Razorpay's signature to `/verify`; the server checks the HMAC and only then marks the booking `confirmed`.
4. Closing the popup releases the seats immediately; abandoned holds also expire on their own (Mongo TTL index).
5. Edge case: if a hold expires during a very slow payment and someone else takes the seat, the payment is refunded automatically and the customer is told.

## Deploy

Frontend: Vercel (Vite). Backend: any Node host (Render/Railway/Fly) + MongoDB Atlas. Set `MONGODB_URI`, `CLIENT_ORIGIN` and the `RAZORPAY_*` variables on the server and `VITE_API_URL` (e.g. `https://your-api.example.com/api`) at frontend build time.
